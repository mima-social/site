# mima.social

The website for [Mima](https://www.mima.social), the calm, private app for all your
social networking, news, and conversations. It's a static site with no build
step.

| File | What it is |
|---|---|
| `index.html` | The landing page |
| `launch.css`, `launch.js` | Its styles and motion: wordmark draw-on, rotating headline, feature tour, timeline scroller, background squiggles |
| `app.js` | Newsletter signup (posts to Loops). The form is also a [WebMCP](https://webmachinelearning.github.io/webmcp/) tool, `subscribe_to_mima_updates` (declarative, with an imperative fallback), and replies to agents with the real result. |
| `llms.txt` | Plain-language summary of Mima for AI assistants and crawlers ([llmstxt.org](https://llmstxt.org)). Keep it in step with the page copy. Its `## Learn` section is generated (see below). |
| `learn/`, `learn-src/` | Learn, the knowledge base: generated pages in `learn/`, Markdown sources and the build script in `learn-src/` (see below) |
| `robots.txt`, `sitemap.xml` | Crawler files, generated by the Learn build |
| `_headers` | Netlify headers: serves the Markdown guides as `text/markdown` |
| `netlify/functions/email-download.mjs` | `/api/email-download`: on phones and tablets, Download opens a sheet that emails the Mac link through Loops (see below) |
| `netlify/functions/email-unsubscribe.mjs` | `/api/email-unsubscribe`: the desktop app calls it when someone withdraws email consent (see below) |
| `_redirects` | Netlify redirects: `/download` → the latest .dmg |
| `oauth/bluesky/client-metadata.json` | Bluesky OAuth client metadata for the desktop app. Must stay at this path on `www.mima.social`. |
| `site-assets/`, `assets/` | Fonts, logo, hero art, app screenshots, fake avatars and photos |
| `app-shots/` | Dummy app pages and the script that renders the app screenshots |
| `PRODUCT.md`, `DESIGN.md` | Product facts and copy rules; the page's design system |
| `tests/`, `.github/workflows/checks.yml` | Unit tests for the build scripts and Netlify function, and the PR check workflow that runs them (see Tests) |

Preview locally from the repo root:

```sh
python3 -m http.server 8765   # then open http://localhost:8765/
```

Add `#tour-compose` or `#tour-conversations` to the URL to open the feature tour
on that tab.

## Learn (the knowledge base)

Guides live at `/learn/`. Each is written in Markdown in `learn-src/articles/`
and built into static pages you commit, so Netlify still has no build step:

```sh
python3 learn-src/build.py   # pages, Markdown copies, sitemap, llms.txt
python3 learn-src/og.py      # a share image per page (needs Google Chrome)
python3 learn-src/build.py   # again, so new pages point at their new images
```

**Share images:** `learn-src/og.py` renders `app-shots/og-learn.html` for every
Learn page to `site-assets/og/<page>.jpg` (2400 × 1260): the title in the
display face, a "Learn · Topic" tag, and the guide's first app picture. Topic
pages show their description too. It skips pages whose title, picture and
template haven't changed, and deletes images for pages that are gone. Until a
page has one, it falls back to the site's `og-image.jpg`.

It writes `learn/index.html`, a page per topic (`learn/topics/<topic>/`), a page
per guide (`learn/<slug>/`) and a Markdown copy of each guide for AI agents
(`learn/<slug>.md`). It also regenerates `sitemap.xml`, `robots.txt` and the
`## Learn` section of `llms.txt`. Edit the sources, never the generated files.

Each article starts with front matter:

```
---
title: How to …
slug: how-to
summary: The answer in one sentence. Shown as "In short", in search results and to agents.
topic: Topic name (must match learn-src/topics.json)
updated: 2026-11-09
published: 2026-11-01   # optional, defaults to updated; sorts the Latest list
order: 3                # position within its topic
related: other-slug, another-slug
mima: Optional one-line pitch for the "Try it in Mima" box
---
```

- **Topics** are in `learn-src/topics.json` (name, slug, one-line blurb), in
  the order the shelves appear. A shelf on the index shows five guides, then links to
  the topic page with all of them.
- **Common questions:** a `## FAQ` (or `## Common questions`) section is also
  published as FAQ structured data. Write each question as a `###` heading, or
  start a paragraph with the question in bold: `**Can I schedule posts?** No.`
- **Markdown supported:** headings, lists, links, bold/italic, inline code, code
  blocks, tables, `>` callouts and images. An image alone on its line becomes
  a captioned figure: `![alt text](/site-assets/app/board.webp "Caption")`. A
  table with more than four columns scrolls sideways with its first column
  pinned. Use raw HTML for anything else.
- **Pictures of the app** come from `app-shots/` (fictional people and posts);
  add a view there rather than using a real screenshot.
- **Claims:** guides follow the same rules as the landing page (`PRODUCT.md`):
  only shipped features, nothing about Windows, Linux or unshipped networks.
- **On phones**, Download on a Learn page goes to `/#get-mima`, which opens the
  home page's email-the-link sheet.

When Mima releases, the `/learn` skill (`.agents/skills/learn/`) turns the
release into new and updated guides and a draft PR.

Before publishing a guide, check every claim about Mima against the app's code
(`mima-social/desktop`, `next` branch), and say in a caption that the people in
app pictures are made up.

## Tests

Unit tests live in `tests/` and use the built-in runners, so there is nothing
to install: `tests/test_*.py` for Python, `tests/*.test.mjs` for Node.

```sh
python3 -m unittest discover -s tests
node --test "tests/**/*.test.mjs"   # Node 24 needs the glob; `tests/` alone fails
```

The **Checks** GitHub Action (`.github/workflows/checks.yml`) runs both on every
pull request and push to `main`, along with the JS syntax check, Python compile,
the `index.html` JSON-LD parse, and a Learn rebuild that fails if the generated
files differ from what's committed.

## Telling search engines about new pages

When a merge to `main` changes `sitemap.xml`, the **Submit new pages** GitHub
Action (`.github/workflows/submit-new-pages.yml`, running
`tools/submit_pages.py`) compares the sitemap with the previous commit, then:

1. waits until Netlify has deployed it (the live sitemap matches the commit);
2. sends every new or updated URL to [IndexNow](https://www.indexnow.org),
   which Bing, Yandex, Seznam and Naver share. The key file is
   `2cc6a4774d121117fdfe713396e952cb.txt` at the site root; keep it there;
3. opens an issue, "Submit N new page(s) to Brave Search", with a checkbox per
   new URL. Brave has no submission API, so submit each one at
   https://search.brave.com/submit-url, tick it, and close the issue.

Google reads the sitemap from Search Console on its own. To submit pages from
an older range again, run the workflow by hand (Actions → Submit new pages →
Run workflow) with an older commit as `base`. Preview what would be sent with
`python3 tools/submit_pages.py --base <commit> --dry-run`.

## App screenshots

Every picture of the Mima app on the page is an image rendered from **dummy
pages** that recreate the real app UI with fictional content. Real screenshots
would show real people. To regenerate them:

```sh
python3 app-shots/build.py   # write the dummy pages from the fake content
sh app-shots/render.sh       # render them with headless Chrome to site-assets/app/*.webp
```

You need Google Chrome and `cwebp` (`brew install webp`).

How it works:
- **Styles:** copied from `mima-social/desktop`.
- **Fake content:** names, `.example` handles, and generated avatars and photos.
- **Window sizes:** each view is rendered at a set size; there's a table in
  the app-shots README.
- **Phones:** separate narrow renders for phone screens.
- **On the page:** the composer zoom types real text over its screenshot, and
  the "Catch up" timeline scrolls behind its screenshot.

Full details are in [`app-shots/README.md`](app-shots/README.md). Keeping the
screenshots in sync with the app is tracked in mima-social/desktop#1396.

## Before launch

- The Download buttons (two links, marked `data-download`) point to
  `https://www.mima.social/download`, which `_redirects` sends (302) to the stable
  `Mima-latest-arm64.dmg` alias in R2. The desktop release pipeline keeps that
  alias current (mima-social/desktop#1406), so `_redirects` never changes per
  release. The alias 404s until that PR ships its first release.
- When the demo video exists, remove `hidden` from `section.demo-sec` in
  `index.html` and swap in the `<video>` markup from the comment there.

## Emailing the download link (phones and tablets)

On touch devices, Download opens a sheet instead of starting a .dmg download that
can't be used there. The Netlify function at `netlify/functions/email-download.mjs`
sends a Loops transactional email with the link. If the person ticks "Also send me
occasional Mima updates" (unticked by default), it also adds them to the mailing
list. New contacts get the Loops source `Mobile download sheet at mima.social 2026.q4`;
existing contacts keep their original source. Either way `optInAt` records when they
agreed, as proof of consent.

It needs these Netlify environment variables:

| Variable | Where it comes from |
|---|---|
| `LOOPS_API_KEY` | Loops → Settings → API |
| `LOOPS_DOWNLOAD_EMAIL_ID` | The transactional email's id. It must use a `downloadUrl` data variable for the link. |
| `LOOPS_MAILING_LIST_ID` | Loops → Audience → Lists |

## Unsubscribing from the app

When someone withdraws email consent in the desktop app (Settings → Privacy,
mima-social/desktop#2318), the app calls `/api/email-unsubscribe`, because it
can't hold the Loops API key. `netlify/functions/email-unsubscribe.mjs` sets the
contact's `subscribed` to false in Loops, which stops all campaign and workflow
email. Transactional email, like the download link, still works. It uses
`LOOPS_API_KEY` only.

Contract: `POST` with `Content-Type: application/json` and `{"email": "…"}`.

| Status | Meaning |
|---|---|
| 200 `{"ok": true}` | Unsubscribed, or the address isn't in Loops (the response doesn't say which) |
| 400 | Bad JSON or an invalid email |
| 405 | Not a POST |
| 502 | Loops failed; the app should retry |

- **Never creates a contact.** Loops' update endpoint creates one when no
  contact matches, so the function looks the address up first.
- **Logs and URL:** the email never appears in our logs or in our URL.
- **Abuse:** anyone who knows an address can unsubscribe it, a trade-off the
  owner accepted (#41). The limits are a per-IP rate limit of 5 a minute, the
  JSON body (a page on another site can't send it without a CORS preflight,
  which the function doesn't answer), and the 200 that doesn't reveal whether
  an address is on the list.
